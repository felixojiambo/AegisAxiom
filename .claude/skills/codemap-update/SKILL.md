# /codemap-update — Refresh CODEMAP.md semantic descriptions

**Trigger:** `/codemap-update [--all | --changed-since <ref> | --files <list>]`
**Purpose:** Populate or refresh the one-line semantic descriptions in
`CODEMAP.md`. Deterministic data in CODEMAP.md (paths, route prefixes,
permission keys) is regenerated by `/init-project-doc` and stays correct on its
own; this skill handles the part that needs an LLM.

You dispatch the `codemap-haiku` agent in small batches. You do not write
descriptions yourself.

---

## Cold start: prerequisites

1. **CODEMAP.md must exist.** If missing, tell the developer to run
   `/init-project-doc` first and stop.
2. **CLAUDE.md should exist.** Doc references for the haiku agent come from
   CLAUDE.md's "Must-read" section plus the project's doc tree. Without it,
   you can still run but description quality drops.
3. **Git repo.** Used for diff-based scoping when invoked without explicit
   file list.

---

## Mode selection

The skill has three invocation modes. Pick by the flag provided, or ask the
developer if none was given:

| Flag | Behavior |
|---|---|
| `--all` | Refresh every entry in CODEMAP.md (use sparingly — cost is N×Haiku calls) |
| `--changed-since <ref>` | Refresh only entries for files changed since `<ref>` (e.g., `origin/dev`) |
| `--files <comma-separated list>` | Refresh exactly the listed files |
| *(no flag)* | Default to `--changed-since $(git merge-base HEAD origin/dev)` |

The PR-open hook always passes `--files` with the structurally-changed file
list. Manual invocations usually want the default.

---

## Phase 1: Compute target file list

```bash
# Default — files structurally changed since branching off dev
BASE=$(git merge-base HEAD origin/dev 2>/dev/null || git merge-base HEAD origin/main)
git diff --name-only "$BASE"...HEAD

# Filter to files that appear in CODEMAP.md
# (we don't describe files that aren't tracked in the map)
```

Read `CODEMAP.md` and build a set of all `path` values referenced in the
tables. Intersect with the target list. The result is the files to describe.

If the intersection is empty, exit cleanly: "Nothing to update — no tracked
files in the change set."

---

## Phase 2: Map files to authoritative docs

For each target file, pick which docs the `codemap-haiku` agent should read
for context. Use this mapping table — adapt to the project's actual doc set
detected from CLAUDE.md's "Must-read" section.

### Default mapping (override per project)

| File path pattern | Authoritative docs |
|---|---|
| `backend/routes/*.py` | `docs/ROUTE_PROTECTION.md`, `docs/PERMISSIONS_GUIDE.md`, `docs/ENGINE_ARCHITECTURE.md` |
| `backend/services/*.py` (top-level) | `docs/ENGINE_ARCHITECTURE.md` |
| `backend/services/ingestion/*` | `docs/ingestion/01a-01e*.md`, `.claude/skills/ingest-app/SKILL.md` |
| `backend/services/ai/*` | `docs/AI_DEVELOPER_GUIDELINES.md`, project AI docs |
| `backend/middleware/*` | `docs/ROUTE_PROTECTION.md` |
| `frontend/src/components/*Portal.js` | `.claude/skills/ingest-app/SKILL.md` § styling, `CLAUDE.md` § frontend conventions |
| `frontend/src/components/*.js` (top-level) | `CLAUDE.md` § frontend conventions |
| `frontend/src/lib/*` | first-30-lines of the file itself (usually documented inline) |
| `scripts/*` | first-30-lines of the file itself |

### Always-included context

For **every** batch, also include:
- `CLAUDE.md` (the project's doctrine)
- The first 30 lines of `README.md` (for project identity)

Cap total docs per batch at **5 files** to keep the haiku agent's context
tight. If a mapping would exceed 5, prioritize the most specific docs.

---

## Phase 3: Build batches

Group target files into batches of **3–8 files each**:

- Files that share the same authoritative doc set go in the same batch
- Mixed-domain batches are OK if the docs overlap
- Never exceed 8 files per batch (haiku agent's accuracy drops past this)
- Aim for batches that share thematic context (all routes in one, all
  services in another) so the agent can reason about them coherently

For each batch, gather:
1. Full content of each target file (or git diff hunk if file is >500 lines)
2. Full content of each authoritative doc in the mapping
3. The current CODEMAP.md description for each file (so the agent can decide
   if its description has drifted)

---

## Phase 4: Dispatch codemap-haiku per batch

Invoke the `codemap-haiku` agent once per batch. Use the `Agent` tool with
`subagent_type: codemap-haiku`. Prompt template:

```
BATCH: <N> files

AUTHORITATIVE DOCS (read these for context):
=== docs/ROUTE_PROTECTION.md ===
<content>

=== CLAUDE.md ===
<content>

FILES TO DESCRIBE:

PATH: backend/routes/projects.py
CHANGE_TYPE: modified
DIFF:
<unified diff>
EXISTING_DESCRIPTION: "PMO project CRUD endpoints"

PATH: backend/routes/chat.py
CHANGE_TYPE: added
FULL CONTENT:
<file content, truncated to 500 lines if needed>
EXISTING_DESCRIPTION: ""

(... more files ...)

Return descriptions per the agent contract.
```

Run batches **sequentially**, not in parallel. The haiku agent is fast (each
batch returns in seconds) and serial dispatch keeps token use predictable and
the cost visible.

Collect all YAML responses into one merged structure.

---

## Phase 5: Validate haiku output

For each returned description:

1. **Length check** — must be ≤100 chars. If over, truncate at the last word
   boundary and log a warning.
2. **`_NEEDS_REVIEW_` flagging** — collect these. Surface them at the end.
3. **Empty / whitespace check** — treat empty as `_NEEDS_REVIEW_`.
4. **Format check** — no leading/trailing whitespace, no trailing period, no
   markdown formatting inside the description.

If more than 30% of the batch came back `_NEEDS_REVIEW_`, **stop and ask the
developer** — either the authoritative-doc mapping is wrong or the haiku agent
is being asked to describe out-of-scope files.

---

## Phase 6: Patch CODEMAP.md surgically

Read CODEMAP.md. For each file with a new description:

1. Locate the row whose `path` field matches
2. Replace the description column **in-place** — preserve the rest of the row
3. If the path is missing from CODEMAP.md entirely, add a row in the
   appropriate section (only if the file matches the section's pattern)

Do **not** rewrite the file. Do **not** reorder rows. Do **not** touch sections
unrelated to the changed files. The diff should be small and readable.

Use the Edit tool with targeted replacements, not Write.

---

## Phase 7: Report

Print to the developer:

```
Updated CODEMAP.md:
  - 12 descriptions refreshed
  - 2 entries added (new files)
  - 1 entry marked _NEEDS_REVIEW_:
      backend/services/ai/conductor.py — diff was a single-line tweak,
      agent couldn't determine role
  - 0 entries removed (file deletions handled separately)

Diff: 14 lines changed in CODEMAP.md

Cost: ~$0.X (estimated, N Haiku calls × ~M tokens avg)
```

If any `_NEEDS_REVIEW_` entries surfaced, ask:
> "Do you want to:
> (a) edit these descriptions manually,
> (b) re-run with broader doc context, or
> (c) leave them as TODOs for next time?"

---

## Phase 8: Hand off

```
CODEMAP.md updated. Recommended next steps:
1. Review the diff: git diff CODEMAP.md
2. Commit alongside your code changes:
   git add CODEMAP.md && git commit -m "chore: refresh codemap descriptions"
3. The PR-open hook will detect future structural changes and prompt this
   skill again — no need to run manually unless you want to refresh
   speculatively.
```

---

## When this skill is called by the PR-open hook

The hook passes the structurally-changed file list via `--files` and writes
a marker file `.codemap-pending.json` containing the diff manifest. When you
detect this marker:

1. Read `.codemap-pending.json` — it has the file list and change types
   pre-classified
2. Skip Phase 1 (the hook already did the diff)
3. Proceed from Phase 2 with the marker's file list
4. After Phase 7, **delete** `.codemap-pending.json` to clear the pending state

If the developer interrupts mid-run, leave the marker in place — the next
session can pick up where this one left off.

---

## Failure modes

| Symptom | Cause | Recovery |
|---|---|---|
| Phase 3 batches all hit `_NEEDS_REVIEW_` | Bad doc mapping or agent confusion | Re-run with `--files` constrained to one file at a time to isolate |
| Phase 6 Edit fails — path not in CODEMAP | CODEMAP missing the file's section | Run `/init-project-doc` to refresh the skeleton, then re-run this |
| Haiku agent returns malformed YAML | Rare; retry the single batch | If repeated, batch is too large — split |
| Hook keeps firing but nothing changes | Marker file not being deleted | Manually `rm .codemap-pending.json` |

---

## Cost expectations

A typical PR-driven invocation:
- 3–8 files changed structurally
- 1–2 batches
- ~2k tokens input per batch (file content + docs), ~500 tokens output
- Haiku 4.5 at current pricing: roughly **$0.01–$0.05 per invocation**

If you ever see a single invocation exceed $0.50, something is wrong — either
the file list is too broad (use `--changed-since`) or batches are too large
(reduce batch size).
